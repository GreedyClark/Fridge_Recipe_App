# PROJECT_GUIDE — інструкція для ШІ-асистента

---

## 1. Про проєкт

- **Назва:** Fridge Recipe
- **Що робить:** веб-застосунок, який знає, що лежить у холодильнику, і підбирає рецепти з наявних продуктів. Рахує калорії, веде журнал і список покупок, імпортує рецепти з інтернету через Gemini.
- **Для кого:** люди, які готують удома (самі або парою, сім'єю), і портфоліо для фрілансу.
- **Репозиторій:** github.com/GreedyClark/Fridge_Recipe_App
- **Живий сайт:** peangqin.pythonanywhere.com
- **Поточна фаза:** Фаза 4 — профіль, імпорт текстом, покупки на HTMX, «Сім'я».
- **Що вже зроблено:**
  - холодильник і довідник ~200 продуктів з USDA, свої продукти;
  - рецепти, «Що приготувати?», категорії, порції;
  - імпорт за посиланням через Gemini, спільна база з TheMealDB;
  - журнал з нормою калорій і скасуванням;
  - список покупок;
  - деплой на PythonAnywhere.
- **Що НЕ робимо зараз:** перехід на Tailwind/daisyUI, PostgreSQL, платний хостинг, мобільний застосунок, відновлення пароля поштою.

## 2. Як зі мною працювати

- Я початківець у Python/Django. Пояснюй коротко, *чому* саме так, але без лекцій.
- Пиши українською.
- Видавай код **повними файлами**, з повним шляхом над блоком (`recipes/views.py`), або архівом зі збереженими шляхами.
- Якщо змінюєш існуючий файл — давай файл повністю, а не шматок «додай сюди».
- Перед великою зміною — спочатку план у 3–5 пунктів, потім код.
- Перед новим екраном — макет на полотні в стилі Plan Drop, потім код.
- Працюємо маленькими кроками: крок → тести → коміт → перевірка.
- Якщо щось неясно — запитай, а не вигадуй.
- Не додавай бібліотеки, яких немає в розділі «Стек», без моєї згоди.

## 3. Стиль коду

- Мінімум коментарів: тільки там, де логіка неочевидна.
- Без докстрінгів, що переказують назву функції.
- Без «Крок 1 / Крок 2», без емодзі в коді та коментарях.
- Код має виглядати як написаний звичайним розробником.
- PEP 8, змістовні назви англійською, f-рядки. Інтерфейс — українською.
- Секрети (ключі API, SECRET_KEY) — тільки через `.env`, ніколи в коді.

## 4. Стек

| Що | Чим |
|---|---|
| Бекенд | Django 5.2 (LTS), Python 3.14 локально / 3.13 на сервері |
| Шаблони | Django templates, спільні шматки — `_partial.html` через `{% include %}` |
| Стилі | Bootstrap 5.3 + своя темна тема Plan Drop (`static/css/style.css`), Tabler Icons |
| Інтерактив | **HTMX** для дій без перезавантаження; невеликі скрипти на чистому JS; Tom Select для пошуку продуктів |
| БД | SQLite (локально й на PythonAnywhere) |
| Зовнішні API | USDA FoodData Central, Google Gemini (`google-genai`), TheMealDB |
| Тести | `manage.py test` (unit та інтеграційні) + **pytest-django / pytest-playwright** для браузерних сценаріїв |
| Конфіг | `python-decouple`, файл `.env` |
| Хостинг | PythonAnywhere, безкоштовний тариф |

### Правила для стеку

- Повторювані шматки шаблонів (картка рецепта, бейдж статусу, кнопка готування) — окремі `_*.html` у теці додатка, а не копіпаст.
- HTMX-відповіді — окремі partial-шаблони (`_shopping_row.html`), view повертає partial, якщо запит від HTMX (`request.headers.get("HX-Request")`).
- Форми — через `ModelForm` / `Form`, валідація в `clean_*`, не у view.
- Запити до БД — без N+1: `select_related` / `prefetch_related`.
- Мережа (USDA, Gemini, TheMealDB, завантаження сторінок) у тестах завжди підмінена.
- Безкоштовний PythonAnywhere пускає лише на сайти з білого списку: Gemini й USDA є, кулінарних сайтів і TheMealDB немає.

## 5. Дизайн

### Дизайн-система Plan Drop

- **Кольори:** фон `#0F0F11`, поверхні `#19191C` / `#232327`, лінії `#2E2E33`, текст `#F3F3F1`, приглушений `#A1A1A7`, акцент лайм `#D3F23A` (текст на ньому `#121212`), попередження `#F5BE55`, помилка `#FF6B5E`.
- **Шрифти:** Oswald — заголовки й великі цифри, Onest — усе інше.
- **Форма:** заокруглення 20 px для карток, 14 px для полів, кнопки-«пігулки» 999 px; висота кнопок і полів від 44 px.
- **Макети:** полотно «Fridge Recipe App — макети», сторінки «Варіант B — Plan Drop» і «Фаза 4».

### Правила «щоб не виглядало як ШІ-шаблон»

- **Ніяких** фіолетово-синіх градієнтів за замовчуванням, «Empowering Your Success», картинок-заглушок і трьох однакових карток «фіч» у ряд.
- Один акцентний колір (лайм), решта — нейтральні. Акцент тільки для головних дій і «свого» (наприклад, «береш ти»).
- Не більше 2 шрифтів. Чітка ієрархія: заголовок, підзаголовок, текст — помітно різні за розміром і вагою.
- Відступи за однією шкалою (4 / 8 / 12 / 16 / 24 / 32 / 48 px), не «на око».
- Багато повітря: краще менше елементів на екрані, ніж тісно; другорядні дії ховаються (наприклад, відкриваються натисканням на рядок).
- Тексти інтерфейсу — конкретні, про цей продукт («Додати продукт», «3 рецепти з того, що є»), а не маркетингова вода.
- Анімації — тільки короткі (150–250 мс) і по ділу.
- Мобільна версія обовʼязкова: спочатку перевіряй на ширині 375 px, без горизонтальної прокрутки.
- Порожні стани, помилки й завантаження теж мають дизайн.
- Контраст тексту — WCAG AA.
